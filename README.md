# VPN Share — веб-панель для Windows 11

**Новая версия v1.2:** локальная веб-панель с визуальным маршрутом **интернет → VPN TUN → Wi-Fi хот-спот → ICS → клиенты → проверка VPN на клиенте**, подсветкой этапов, диагностикой, выбором адаптеров и настройкой ICS одной кнопкой.

## Быстрый запуск v1.2

1. Нажмите **Code → Download ZIP** на GitHub и распакуйте архив.
2. Подключите интернет к Windows 11 через USB-модем телефона **или** Wi-Fi.
3. Включите VPN Happ / Hub с режимом TUN.
4. В Windows откройте **Параметры → Сеть и Интернет → Мобильный хот-спот** и включите Wi-Fi-раздачу.
5. Запустите **Start.cmd**. Подтвердите запрос администратора.
6. Автоматически откроется браузер с панелью на **http://127.0.0.1:18761/** (если порт занят, используется следующий свободный до 18780). Интернет для самого веб-интерфейса не требуется.
7. Выберите **A: входящий USB/Wi-Fi**, **B: VPN TUN**, **C: Microsoft Wi-Fi Direct**. Нажмите **Сохранить выбор**.
8. Нажмите **Настроить ICS** и подтвердите изменение системных настроек. Если ICS уже настроен правильно, изменений не будет.
9. Подключите Quest 3 или другое устройство к точке доступа. Проверьте внешний IP, DNS и IPv6 **на самом устройстве**.

Веб-интерфейс работает **только на ноутбуке**, слушает адрес `127.0.0.1`, не выставляется в локальную сеть и не использует облачный сервер. Для работы нужен штатный Windows PowerShell 5.1, установка Node.js или Python не требуется. Закройте окно PowerShell, чтобы остановить веб-сервер.

### Значение цветов маршрута

| Узел | Зелёный означает | Ограничение |
|---|---|---|
| Интернет | Входящий интерфейс Up и есть IPv4-маршрут по умолчанию | Это не проверка доступа к интернет-сайту |
| VPN TUN | Интерфейс Up и есть маршруты VPN | Не гарантирует успешную связь с VPN-сервером |
| Wi-Fi | Wi-Fi Direct Up | Не подтверждает доступность хот-спота для клиентов |
| ICS | В Windows общий доступ направлен с VPN на Wi-Fi Direct | Не гарантирует, что весь трафик клиента идёт через VPN |
| Устройства | Windows видит хотя бы одного IPv4-соседа на Wi-Fi Direct | Не всегда соответствует фактически подключённым устройствам |
| VPN клиента | Всегда жёлтый — «Не подтверждено» | Для достоверной проверки нужен тест на самом клиенте |

**Счётчик устройств — приблизительный.** Он считает наблюдаемые IPv4-соседства, а не точное число активных подключений. Отображаемые IP могут быть устаревшими, а некоторые клиенты не отображаются. Веб-панель не должна показывать зелёный статус «VPN клиента», пока нет реальной проверки с этого устройства.

### Если ICS не включается

В панели есть кнопки **Сетевые подключения** (открывает `ncpa.cpl`) и **Настройки хот-спота**. Для ручной настройки:

1. Включите VPN TUN и мобильный хот-спот.
2. Откройте `ncpa.cpl` и найдите VPN TUN (например, `happ-default-tun`).
3. Правой кнопкой → **Свойства → Доступ**.
4. Отметьте разрешение общего доступа.
5. Выберите **Microsoft Wi-Fi Direct Virtual Adapter** как домашнее подключение.
6. Нажмите ОК и обновите панель.

При автоматической настройке приложение может отключить ранее настроенный ICS и попытается восстановить старые роли при ошибке. Перед нажатием кнопки убедитесь, что выбраны нужные интерфейсы. На рабочих компьютерах используйте только с разрешения администратора.

## Дополнительная документация прежней версии

**VPN Share** — бесплатная утилита с графическим интерфейсом для Windows 11. Она помогает раздать интернет через VPN (TUN) с ноутбука на другие устройства по Wi-Fi с помощью встроенной функции Windows **Internet Connection Sharing (ICS)**.

Пример: телефон раздаёт интернет ноутбуку по USB или ноутбук получает интернет по Wi-Fi → VPN Happ в режиме TUN → мобильный хот-спот Windows → Meta Quest 3, телефон, планшет или другое устройство.

> **Статус:** предыдущая версия утилиты работала на одном пользовательском компьютере с Windows 11, Happ TUN и Wi-Fi Direct. Опубликованная версия VPN Share — переработанная реализация, не прошедшая отдельные испытания на реальной Windows. Работа с другими VPN-клиентами не гарантируется.

## v1.1 — индикаторы и помощь по ICS

В окне появились шесть автоматически обновляемых индикаторов (раз в 5 секунд):

| Индикатор | Зелёный означает | Что **не** гарантируется |
| --- | --- | --- |
| Internet | Входящий адаптер активен и имеет IPv4-маршрут по умолчанию | Доступность сайтов |
| VPN TUN | VPN-адаптер активен и имеет маршруты общего IPv4-трафика | Что VPN-сервер действительно отвечает |
| Hotspot | Виртуальный Wi-Fi Direct-адаптер активен | Что клиент получил интернет |
| ICS | Windows ICS назначен с VPN на Wi-Fi Direct | Что трафик клиента не обходит VPN |
| Client | На интерфейсе хот-спота замечен сосед в таблице IPv4 | Что это точно подключённый клиент с рабочим интернетом |
| Client VPN | Всегда **NOT VERIFIED** | Проверка возможна только со стороны подключённого устройства |

**Как быстро настроить ICS:** выберите три адаптера, включите VPN и хот-спот, нажмите **Configure ICS**. Если Windows откажет, нажмите **ICS guide / manual steps** — откроется пошаговая инструкция, а кнопка **Network connections** сразу откроет `ncpa.cpl`. Скриншоты в этой версии не встроены: руководство открывает нужные системные окна, но не управляет ими скрытно.

**Почему нет зелёной галочки «VPN работает на Quest»:** без проверки на Quest нельзя достоверно определить внешний IP, DNS и IPv6 клиента. Программа сознательно показывает `NOT VERIFIED`, а не вводит в заблуждение.

## Требования

- Windows 11, Windows PowerShell 5.1, права администратора.
- Wi-Fi-адаптер с поддержкой **Мобильного хот-спота Windows**.
- Интернет на ноутбуке (USB-модем Android или обычный Wi-Fi).
- VPN-клиент с настоящим сетевым **TUN/TAP-адаптером**. Режим только системного прокси не подходит.

Не требуется Python, Node.js, отдельная установка PowerShell или root на телефоне.

## Установка и запуск

1. На странице репозитория нажмите **Code → Download ZIP**.
2. Распакуйте архив в обычную папку (не запускайте файлы прямо из ZIP).
3. Откройте `Start.cmd`. Windows запросит права администратора — подтвердите. Можно предварительно прочитать `VPNShare.ps1`.
4. Откроется окно VPN Share с тремя выпадающими списками и журналом событий.

`Start.cmd` запускает локальный PowerShell-скрипт. Утилита не скачивает сторонние исполняемые файлы и не запрашивает VPN-пароли.

## Подключение — вариант A: телефон → USB → ноутбук

1. Подключите Android-телефон к ноутбуку USB-кабелем.
2. На телефоне включите **USB-модем / USB tethering**. Убедитесь, что интернет работает на ноутбуке.
3. В VPN-клиенте на ноутбуке подключитесь к серверу и включите **TUN mode**.
4. Откройте **Параметры Windows → Сеть и Интернет → Мобильный хот-спот**.
5. Включите хот-спот, выберите раздачу через Wi-Fi, запомните имя сети и пароль.
6. Запустите VPN Share, нажмите **Refresh adapters** и выберите три интерфейса согласно таблице ниже.

## Подключение — вариант B: Wi-Fi → ноутбук → Wi-Fi

Windows 11 может одновременно получать интернет по Wi-Fi и раздавать его через мобильный хот-спот, если драйвер Wi-Fi-адаптера это поддерживает.

1. Подключите ноутбук к существующей Wi-Fi-сети.
2. Включите VPN в режиме TUN.
3. Включите мобильный хот-спот Windows.
4. Обновите интерфейсы в VPN Share и выберите входящий Wi-Fi, VPN TUN и виртуальный Wi-Fi Direct.

## Какие интерфейсы выбирать

| Поле | Что выбирать | Пример |
| --- | --- | --- |
| **A. Incoming internet** | Адаптер, через который ноутбук получает обычный интернет | `Ethernet 3 — SAMSUNG Mobile USB Remote NDIS` **или** `Wi-Fi — MediaTek Wi-Fi 6` |
| **B. VPN TUN adapter** | Активный виртуальный адаптер VPN | `happ-default-tun — SocksTunnel Tunnel` |
| **C. Microsoft Wi-Fi Direct** | Виртуальный адаптер работающего мобильного хот-спота | `Local Area Connection* 2 — Microsoft Wi-Fi Direct Virtual Adapter #2` |

**Важно:** источник ICS — **B (VPN)**, а получатель — **C (Wi-Fi Direct)**. Поле A служит для проверки схемы, оно **не** должно становиться источником ICS. Не выбирайте обычный физический Wi-Fi-адаптер в поле C.

## Включение общего доступа (ICS)

1. Убедитесь, что VPN подключён, хот-спот включён, а B и C имеют статус `Up`.
2. Нажмите **Check configuration**. Приложение проверит три различных адаптера и наличие IPv4-маршрутов через VPN.
3. Если в журнале написано `ICS already matches VPN -> Wi-Fi Direct`, настройка уже есть. **Не перенастраивайте её**.
4. Если ICS не совпадает, нажмите **Configure ICS**. Приложение использует системный COM API `HNetCfg.HNetShare`: назначает VPN роль **public/source** и Wi-Fi Direct роль **private/destination**.
5. Если Windows уже использует ICS для другого подключения, приложение попросит подтверждение перед изменением. При ошибке программа попытается восстановить прежние роли, но успешный откат не гарантируется.
6. Ещё раз нажмите **Check configuration**.

Для ручной настройки нажмите `Win + R`, введите `ncpa.cpl`, откройте свойства VPN TUN → **Доступ** → разрешите общий доступ и выберите виртуальный Wi-Fi Direct-адаптер. Не все VPN-драйверы показывают вкладку «Доступ».

## Проверка на Quest 3 или другом устройстве

1. Подключитесь к Wi-Fi сети хот-спота ноутбука.
2. Откройте на подключённом устройстве `https://2ip.ru` или другой сервис определения внешнего IP.
3. Сравните IP с внешним IP ноутбука при включённом VPN. Проверьте также DNS и IPv6.
4. Проверьте поведение при отключении VPN. **Утилита не реализует kill switch**: возможен выход в интернет в обход VPN.
5. Если хот-спот или VPN перезапускались, проверьте роли ICS повторно: Windows может их сбросить.

Совпадение IP в браузере — полезный тест, но не доказательство того, что весь трафик всех приложений идёт через VPN.

## Если не работает

| Симптом | Что проверить |
| --- | --- |
| В списке B нет VPN | Включён ли именно TUN, а не только системный прокси? Нажмите Refresh adapters |
| В списке C нет Wi-Fi Direct | Включён ли мобильный хот-спот Windows? Поддерживает ли драйвер Wi-Fi его работу? |
| Ошибка `0x80040201` | Windows не смогла применить роли ICS. Проверьте, что оба интерфейса активны, служба SharedAccess работает, и попробуйте ручную настройку через `ncpa.cpl` |
| Quest подключается, но нет интернета | Проверьте IP, DNS, наличие ролей ICS и маршруты VPN; перезапуск VPN/хот-спота мог сбросить ICS |
| В поле A нет USB | Убедитесь, что телефон включил USB-модем, а Windows видит сетевой RNDIS-адаптер |
| VPN на ноутбуке работает, но на клиентах обычный IP | ICS может быть привязан не к VPN TUN, а к физическому адаптеру. Перепроверьте B и C |

Кнопка **Save diagnostics** сохраняет список сетевых адаптеров, ICS и IPv4-маршрутов в TXT на рабочем столе. Перед публичной публикацией отчёта удалите локальные адреса и другую чувствительную информацию.

## Безопасность и ограничения

- Скрипт требует права администратора, потому что изменяет системные настройки общего доступа.
- Программа не включает и не настраивает VPN-клиент: VPN запускается отдельно.
- Не изменяйте сетевые настройки на рабочем или корпоративном ПК без разрешения администратора.
- ICS не обеспечивает криптографической защиты сам по себе и не гарантирует отсутствие IPv6/DNS-утечек.
- Код открыт для аудита; запуск выполняется на ваш риск.
